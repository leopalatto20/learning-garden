# Learning Space

A personal digital garden for courses, self-study, and research. Raw material enters through `inbox/`; atomic, linked study notes live in the garden and mature over time.

## Layout

| Path | Purpose |
|---|---|
| `inbox/` | Raw class notes, grouped by subject in `inbox/<subject>/`; root files are unsorted |
| `slides/` | Professor slide decks, named `<course>-<topic>-<date>` when known |
| `research/` | Papers, articles, and documentation, one file per source |
| `notes/` | Curated atomic notes, one concept per file |
| `maps/` | Course indexes linking every note they cover |
| `study/` | Generated exam material |
| `outputs/` | Q&A answers generated by `ask-garden` |
| `archive/` | Processed raw notes |

## Curated note contract

- **Atomic**: one concept per note. Split titles that need “and”.
- **Filename**: canonical concept name in kebab-case; it is also the wikilink target.
- **Frontmatter**: `course`, `tags`, `created`, and `updated`.
- **Links**: use Obsidian wikilinks. Every note has a short `Links` section explaining why each neighbor relates.
- **Math**: in `notes/`, `maps/`, and `study/`, wrap inline expressions in `$...$` and display expressions in `$$` delimiters on separate lines. Never leave LaTeX commands or formulas bare. Preserve `inbox/` exactly; normalize math only in curated output.
- **Diagrams**: add Mermaid when a concept benefits from visual structure, such as an algorithm, pipeline, state machine, taxonomy, proof, decision tree, flow, timeline, or message sequence.
- **Honesty**: enrich from general knowledge when useful; mark uncertain or not-from-lecture material with `> [!warning] Not from lecture`.

## Workflows

- New raw notes in `inbox/` → use `process-notes`. A subject name scopes processing to `inbox/<subject>/`; without one, process every subject.
- A new deck in `slides/` → use `enrich-slides`.
- A new paper, article, or documentation source in `research/` → use `enrich-research`.
- Exam preparation → use `exam-prep`.
